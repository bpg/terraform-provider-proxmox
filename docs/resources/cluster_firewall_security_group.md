# Resource: proxmox_cluster_firewall_security_group

Manages a cluster-level firewall security group and its rules. A security group is a collection of rules that can be referenced from cluster, node, VM and container rules.

Rules are applied in the order of the `rule` blocks. The resource owns every rule in the group: rules added outside
Terraform are removed on the next apply.

## Example Usage

```terraform
resource "proxmox_cluster_firewall_security_group" "webserver" {
  name    = "webserver"
  comment = "Managed by Terraform"

  rule {
    type    = "in"
    action  = "ACCEPT"
    comment = "Allow HTTP"
    dest    = "192.168.1.5"
    dport   = "80"
    proto   = "tcp"
    log     = "info"
  }

  rule {
    type    = "in"
    action  = "ACCEPT"
    comment = "Allow HTTPS"
    dest    = "192.168.1.5"
    dport   = "443"
    proto   = "tcp"
    log     = "info"
  }
}
```

## Schema

### Required

- `name` (String) Security group name. Must be lowercase, because PVE lowercases security group names. Changing it renames the group in place, and PVE updates the rules that reference it.

### Optional

- `comment` (String) Security group comment.
- `rule` (Block List) Firewall rule, in evaluation order (multiple blocks supported). (see [below for nested schema](#nestedblock--rule))

### Read-Only

- `id` (String) The security group name.

### Nested Schema for `rule`

Required:

- `action` (String) Rule action (`ACCEPT`, `DROP`, `REJECT`).
- `type` (String) Rule type (`in`, `out`, `forward`).

Optional:

- `comment` (String) Rule comment.
- `dest` (String) Restrict packet destination address. This can refer to a single IP address, an IP set ('+ipsetname') or an IP alias definition. You can also specify an address range like '20.34.101.207-201.3.9.99', or a list of IP addresses and networks (entries are separated by comma). Please do not mix IPv4 and IPv6 addresses inside such lists.
- `dport` (String) Restrict TCP/UDP destination port. You can use service names or simple numbers (0-65535), as defined in '/etc/services'. Port ranges can be specified with '\d+:\d+', for example '80:85', and you can use comma separated list to match several ports or ranges.
- `enabled` (Boolean) Enable this rule. Defaults to `true`.
- `log` (String) Log level for this rule (`emerg`, `alert`, `crit`, `err`, `warning`, `notice`, `info`, `debug`, `nolog`).
- `macro` (String) Use predefined standard macro.
- `proto` (String) Restrict packet protocol. You can use protocol names or simple numbers (0-255), as defined in '/etc/protocols'.
- `source` (String) Restrict packet source address. This can refer to a single IP address, an IP set ('+ipsetname') or an IP alias definition. You can also specify an address range like '20.34.101.207-201.3.9.99', or a list of IP addresses and networks (entries are separated by comma). Please do not mix IPv4 and IPv6 addresses inside such lists.
- `sport` (String) Restrict TCP/UDP source port. You can use service names or simple numbers (0-65535), as defined in '/etc/services'. Port ranges can be specified with '\d+:\d+', for example '80:85', and you can use comma separated list to match several ports or ranges.

Read-Only:

- `pos` (Number) Position of the rule in the security group.

## Import

Import is supported using the following syntax:

```shell
terraform import proxmox_cluster_firewall_security_group.webserver webserver
```

## Migrating from `proxmox_virtual_environment_cluster_firewall_security_group`

Use a `moved` block (Terraform 1.8 or later) to move existing state without recreating the group:

```terraform
moved {
  from = proxmox_virtual_environment_cluster_firewall_security_group.webserver
  to   = proxmox_cluster_firewall_security_group.webserver
}
```

Differences from the legacy resource:

- `rule.security_group` and `rule.iface` are not available: PVE rejects both in security group rules.
- `rule.action` and `rule.type` are required.
- The `node_name`, `vm_id` and `container_id` attributes, which had no effect, are removed.
- Unset optional strings are `null` instead of `""`, and setting them to `""` is rejected.
