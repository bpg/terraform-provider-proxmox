# Resource: proxmox_ceph_fs

~> **Experimental.** Schema and behavior may change in future releases. Pin the provider version if stability matters.

Manages a CephFS on the Proxmox VE cluster's own Ceph cluster. Proxmox VE creates the filesystem with a new metadata pool and data pool, and only while a metadata server (MDS) is in standby. Mount it with a `proxmox_storage_cephfs`.

Proxmox VE refuses to create a CephFS while no metadata server is in standby. The provider retries that for about a minute, so a metadata server started in the same apply has time to get there.

Proxmox VE always creates the two pools under the cluster's default CRUSH rule and size. Settings in `metadata_pool` and `data_pool` are applied right after creation, so the pools spend a moment on the defaults first.

!> **Destroying a CephFS is manual.** Proxmox VE documents removing a CephFS as a [procedure done by hand](https://pve.proxmox.com/pve-docs/chapter-pveceph.html#_destroy_cephfs), and the web UI has no destroy. While the filesystem exists, destroying this resource fails with those steps: disconnect its clients and disable and remove its storages, unmount them on every node, make sure no metadata server serves it (`ceph fs fail <name>`), then `pveceph fs destroy <name> --remove-pools 1`. Once it's gone, run the destroy again. The same applies when a change to `name`, `node_name` or `pg_num` would replace it.

## Example Usage

```terraform
resource "proxmox_ceph_fs" "shared" {
  node_name = "pve"
  name      = "shared"
  pg_num    = 32

  metadata_pool = {
    size     = 3
    min_size = 2
  }

  data_pool = {
    crush_rule = "replicated_hdd"
    size       = 3
    min_size   = 2
  }
}

resource "proxmox_storage_cephfs" "shared" {
  id      = "shared"
  fs_name = proxmox_ceph_fs.shared.name
  content = ["backup", "iso", "vztmpl", "snippets"]
}
```

## Schema

### Required

- `name` (String) The filesystem's name. Proxmox VE names its pools `<name>_metadata` and `<name>_data`.
- `node_name` (String) The node used to dispatch the API calls. Any node running Ceph works; the filesystem is cluster-wide.

### Optional

- `data_pool` (Attributes) The filesystem's data pool, `<name>_data`. Proxmox VE creates it under the cluster's default CRUSH rule and size; settings given here are applied right after creation and can be changed in place. (see [below for nested schema](#nestedatt--data_pool))
- `metadata_pool` (Attributes) The filesystem's metadata pool, `<name>_metadata`. Proxmox VE creates it under the cluster's default CRUSH rule and size; settings given here are applied right after creation and can be changed in place. (see [below for nested schema](#nestedatt--metadata_pool))
- `pg_num` (Number) The number of placement groups for the data pool at creation; the metadata pool gets a quarter of it, and at least 8. Proxmox VE defaults to 128. Only used at creation, since the PG autoscaler may change it later; changing it replaces the filesystem.

### Read-Only

- `id` (String) The unique identifier of the filesystem: its name.
